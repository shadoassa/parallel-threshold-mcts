# 進捗

- Claude Codeと作成したMPIプログラムの問題点発掘
- 根ノード担当プロセスに負荷が集中している状況を解消する必要がある
- 現在は比較的早く解消できそうな実行停止確認による負荷上昇に対処中
- 根ノードの負荷を分散させる・大量のプロセスによる並列化が活きる設計を新たに考える
- 768コアで動かしていないのでそちらで旧・新コードの実験データも取る

## 状況

前回の進捗報告時にMPI実装での動作を確認した.
Claude Code と色々実験しながら検証したところ,
- サンプリングの時間がほぼ一瞬で終わる
- 根ノード(とその付近)担当プロセスに負荷が集中する形式
 > ↳ 基本的にノード担当以外のプロセスがほとんどアイドル状態になる
- 根ノードで毎回実行停止確認(STOPメッセージの送信のため)の処理が入る

で性能が低下してると思われる.  
(最初の実装なので起こるだろうとは想定していた問題ではあるが...)

## 改善案
どうにか根ノードの負荷を分散させる必要がある.
加えて, 768コアで動作させることを考えると,
そもそも探索木にノードが768個無いと今の設計では意味がない.

根ノードがボトルネックとなっているのは,
- 全DRAWメッセージの送信を担当している
- UPDATEを受け取るたびに統計情報更新・実行停止確認処理が入る

の2つが主に原因となっていると思われるので,
まず比較的早く解消できそうな実行停止確認による負荷上昇の解消に手を付けている

## 次週までの目標
- 実行停止確認処理による負荷上昇を軽減する設計を構想・実装する
- uraniumで動かしてみる
- 768コアで動かしたときの実験データをまとめる

## 達成しなければならないこと
- 並列度が上がれば上がるほど効果が出る並列化設計の考案
- 根ノード担当プロセスの負荷が分散する並列化設計の考案
