## 実装手法

- アルゴリズム: RD-Tracking-MCTS (`Alg_WN_Dtracking`) のMPI並列化
- 並列化方式: コーディネーター・ワーカー型
  - rank 0 が木の全状態を管理 (選択・更新・停止判定)
  - rank 1以降はサンプリング専用ワーカー (Bernoulliサンプル→報酬返送)
- ノード割り当て: `node_id % P` のハッシュ均等割り当て (P = プロセス数)
- メッセージ種別: `TAG_DRAW` (rank0→worker), `TAG_REWARD` (worker→rank0), `TAG_STOP` (試行終了)
- 問題のブロードキャスト: 試行開始前に `MPI_Bcast` で全ランクに問題構造を配布
- 実装ファイル: `src/proposed/experiment_mpi.cpp`

## 考察

- **逐次版より遅い原因 (np=1 比較)**
  - `mpirun` 起動コスト + MPI通信オーバーヘッドが支配的 (逐次版の約3.7倍)
  - Bernoulliサンプリング (~10 ns/回) 自体はほぼコストゼロ

- **tau_avg の差異について**
  - origin 901.9 vs proposed 665.3 の差 (約236) は, stddev ≈ 2000, n=500 での標準誤差 ≈ 89 の約2.6σ
  - アルゴリズムの差ではなく, 乱数シードの違いによる確率的変動の範囲内と判断

- **コア数を増やしても高速化しない原因**
  - 木の計算 (`calc_d_value`, `calc_weight`, `calc_Z`) は rank 0 のシリアル処理のまま
  - コーディネーター・ワーカー型では, 並列化の恩恵はサンプリングコストが律速になる問題でのみ発現

- **次ステップの候補**
  1. **Virtual Loss によるインフライト並列化**: 根が複数のDRAWを同時発行し, サンプリングを並行処理. サンプリングコストが高い問題では有効.
  2. **木計算の分散化**: `calc_d_value`/`calc_weight` をノードごとに分散し, DRAW/UPDATE/STOPの完全実装. 設計難度は高い.
